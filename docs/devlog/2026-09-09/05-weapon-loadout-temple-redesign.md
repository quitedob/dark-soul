# 全关卡建模、独立兵器栏与 Boss 场地互动

完成验证：2026-09-10。当前 [Chrome 试玩](http://127.0.0.1:8129/campaign-final/index.html) 使用最终 Web 导出；本地服务需要保持运行。

承接 [武器挥砍与时序修复](04-weapon-swing-visual-timing.md)。用户继续指出切换武器、UI、场景规模与建模不足，随后明确要求修复全部场景，并让 Boss 的血量阶段和技能真正作用于场地。

## 已落地的装备与界面

- X / 手柄方向左轮换三个右手兵器栏；I / 方向下打开或关闭装备菜单。起始提供直剑、刑天战斧、陨星大剑。更换兵器保留角色身体、骨架、相机、职业与左手装备，使用所选 WeaponData 的伤害、耐力、招式与战技。
- 装备菜单支持选择栏位和分配已拥有的兵器；暂停菜单、背包也能进入装备。菜单恢复之前的暂停、光标和焦点状态。
- 三个栏位和当前栏写入现有标量 progression_values；恢复时先还原职业/身体，再还原兵器。装载过程屏蔽自动存档，避免中间状态覆盖待恢复的配置。
- HUD 改为细生命/耐力/专注条、独立余烬数、三个兵器图标和地点名；标题、暂停、帮助、背包、装备使用同一主题与字体。
- Tab / 1–5 保留为旧职业整套装备切换，不再把它当作独立兵器轮换。Manny 尚无真实拉弓/放箭动作，因此弓未进入新的快捷兵器目录。

## 场景资产与布置

首关由 `tools/build_awakening_temple.py` 在 Blender 中生成真实网格：石质地坪、厚基础、雕刻柱、曲面瓦顶、山门、回廊、双侧殿、石灯、古柏和岩山。首关有 245 个相连六米地面单元，可行走面积 8,820 平方米，整体范围 102 × 150 米。碰撞和模型使用同一布局清单，出口、近路和六处敌人站位显式定位。

其余关卡使用 `tools/build_campaign_environment_kits.py` 创建的五套模块化建模资产；每套包含 Floor、Bridge、Rail、Column、Gate、Landmark、Rock、ArenaCover 共八类部件。五章分别采用寺院石雕、砖墙锻炉、竹林月门、金玉楼阁、黑曜熔炉造型。运行时组合真实导入网格并批量提交，不再显示旧 BoxMesh 地板和六棱占位柱。

Blender 源文件、五套组件预览、尺寸/三角形报告保存在 `build/temple-redesign-20260909/`。新增环境资产位于 `game/assets/environment/`，不改动既有 86 个动画模型的转换清单。

Chrome 首次目检发现亮度偏白、树冠规则、侧殿入口树冠遮满镜头和侧殿内部过暗。已调整 sRGB/线性材质颜色、树冠与山体轮廓，移动入口古柏，补树干/树冠碰撞及侧殿碑台、灯火。

全关卡浏览器复查又发现血铁偏红、天界过曝、天际线空白、近路门和故事道具仍为方块。已将五章和 Boss 阶段灯光调整为可辨认材质与攻击轮廓的色调，增加渐变天空；其余 28 关各使用 50–82 处远景岩体，保留八米以上地面/相机净空。近路门、机关和平台增加切角、拼接、金属配件；钟门、晶石台、轮回环、九石碑与供茶使用独立网格造型并投射到真实地面。中间 `temple-v1` / `temple-v2` / `campaign-v1` 仅作问题定位证据。
