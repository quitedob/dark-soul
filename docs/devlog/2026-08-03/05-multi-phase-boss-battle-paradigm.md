## 二、对比结论（三阶段讨伐战 vs 项目现状）

| 维度 | 三阶段讨伐战原型 | Ashen Hollow 现状 |
|---|---|---|
| Boss 阶段 | 血量阈值 3 阶段 + 无敌变身 + 清弹幕 | phase 手动切换，静态内容变换，无血量触发 |
| 玩家循环 | 移动/射击/护盾/能量/结算 | three.js 展示层无玩家；**Godot 侧已有完整战斗** |
| 场景互动 | 可破坏石柱/水晶回血/陨石预警/子弹拦截 | 展示层无互动；Godot 有机关/传送/死亡循环 |
| 弹幕/AI | 冲击波/追踪弹/陨石/弹幕螺旋/瞬移 | 展示层无；Godot 有 Boss 行为 |
| 调参 | 全参数化 | SCENE-SPECS 纪律 + Godot 平衡数据 |

**核心判断**：三阶段讨伐战是**规则层**完整范式；项目真玩法在 Godot 已实现（阶段/战斗/FSM），three.js 展示层缺玩家循环与互动。**不是缺能力，是分工不同**——§11 作为两端（Godot 调参 / three.js 沙盒）的机制基准。
