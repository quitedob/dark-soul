# 《焰渊》战斗语法：处决、格挡、韧性、招式与兵器诀

> **文档职责：** 本文件定义《焰渊》的原创近战战斗目标。它抽象借鉴类魂游戏对距离、朝向、精力和硬直窗口的重视，但不复刻任何既有作品的动作资产、逐帧数据、招式命名或数值。
>
> **实现状态：** 当前原型已具备轻/重击、**蓄力重击（三档）**、闪避、跑/翻滚/后撤/跳/下落攻、**单持/双持/成对持握切换**、**Guard Meter / 玩家破防**、**人型弹反易处决与背刺**、**五主 Boss Execution Break + 弱点处决（叙事血量地板）**、**GrabPairedDirector 程序化抓投配对**、**CombatCameraDirector 专属镜头**、**命运选择 UI（字符串 choice_flags）**、装备化格挡与弹反、敌人简化韧性、霸体和 9 类 **WeaponArtData** 兵器诀（resources/weapon_arts/ + weapon_arts_catalog.gd，L-13）；**直剑 AnimationTree root-motion POC** 已接入；真实 `.glb` 配对动画与阶段转场 VFX 仍可继续打磨。

## 核心原则

《焰渊》的战斗不以“记住固定连招”作为唯一深度，而以五项判断构成每次交锋：

1. **距离：** 武器覆盖、踏步长度、攻击落点和绕侧空间。
2. **朝向：** 盾角、背部扇区、锁定转向和攻击侧面暴露。
3. **精力：** 攻击、闪避、格挡、冲刺共享资源，不能无风险连续行动。
4. **韧性：** 攻击是否能坚持完成、敌人何时硬直、Boss 何时暴露弱点。
5. **承诺：** 高伤害、高削韧和强位移必须对应更长前摇、后摇或资源成本。

设计口诀：**翻滚奖励时机，跳跃奖励空间判断，格挡奖励资源管理，弹反奖励预测，处决奖励此前建立的破绽。**

## 术语边界

| 机制 | 本质 | 防御窗口 | 主要用途 | 不应承担的功能 |
|---|---|---|---|---|
| 闪避翻滚 | 带位移的短时回避 | 全身短暂无敌窗 | 穿越即时攻击判定 | 不应免费取消所有攻击后摇 |
| 后撤步 | 快速小距离脱离 | 默认无全身无敌 | 拉开轻击、诱导空挥、接后撤反击 | 不应替代翻滚 |
| 跳跃 | 垂直空间动作 | 仅下半身对标记为 `low_sweep` 的攻击免疫 | 跨越低扫、地面震波和低矮障碍 | 不应躲避高位横扫、追踪抓投或全身爆炸 |
| 抓投 | 独立抓取体积触发的配对动作 | 默认不可格挡、不可弹反 | 惩罚被动举盾、错误站位和迟读招 | 不得复用普通武器 Hitbox |
| 跳攻 | 跳跃后的攻击派生 | 不提供额外全身无敌 | 高削韧、压制地面攻击 | 不应成为安全接近按钮 |
| 下落攻 | 高低差触发的落点攻击 | 无额外无敌 | 奖励垂直关卡探索和落点判断 | 不应在平地随时使用 |

攻击标签必须明确表达交互：`low_sweep`、`ground_wave`、`unblockable`、`unparryable`、`grab`、`projectile`、`weak_point`。空间免疫由标签与身体分区共同判断，不由动画名称猜测。

## 动作家族

每个**武器类别**定义完整动作家族；具体武器继承类别动作，再覆盖少量动作、战技和数值。不是每把武器都必须拥有所有动作。

| 动作 | 输入上下文 | 战术目标 | 主要代价 |
|---|---|---|---|
| 单持轻击 | 中立 + 轻击 | 试探、确认、短连段 | 低伤、低削韧、易被霸体换血 |
| 单持重击 | 中立 + 重击 | 破防、打断、惩罚空挥 | 中高精力和恢复 |
| 蓄力重击 | 按住并释放重击 | 逼迫闪避、强削韧、打盾 | 明显蓄势、转向锁定、可被抢攻 |
| 双持轻击 | 双持姿态 + 轻击 | 扩大覆盖、强化压制 | 失去副手防御、较高精力 |
| 双持重击 | 双持姿态 + 重击 | 高承诺打断和换血 | 长前后摇、有限转向 |
| 跑攻 | 冲刺中攻击 | 追击与封走位 | 精力叠加、命中后不宜直接安全连段 |
| 翻滚攻 | 翻滚恢复窗攻击 | 躲后反击 | 短距离、低伤、重复使用可预测 |
| 后撤攻 | 后撤步恢复窗攻击 | 诱导后反制 | 后撤本身无默认无敌 |
| 跳攻 | 空中攻击 | 跨低扫并高削韧 | 落点固定、空中受击风险 |
| 下落攻 | 高度与落点满足条件 | 垂直处决和环境奖励 | 失败落点、坠落伤害、长恢复 |

### 蓄力重击（当前原型）

输入：地面中立时**按住**右副键（RMB / `K`），**松开**释放。冲刺 / 翻滚窗 / 后撤窗 / 空中语境**不进蓄力**，直接出对应语境招。

| 档位 | 按住阈值（默认） | HUD 提示（仅提示模式） | 说明 |
|---|---|---|---|
| T1 | ≥ 0.20s | `CHARGE T1` | 短蓄；更短按仍可走一档或中立重击回退 |
| T2 | ≥ 0.75s | `CHARGE T2` | 中蓄，更高伤/削韧 |
| T3 | ≥ 1.40s | `CHARGE T3` | 满蓄；蓄力中持续扣精力，耗尽或超时自动释放 |
| 开始蓄力 | — | `CHARGING` | 进入 `CHARGE_HEAVY` 架势 |

数据：`ChargeProfile`（离散三档 `AttackData`，不做连续插值）。双持时伤害/精力仍乘 **×1.3 / ×1.5**。

### 上下文优先级

同一输入只解析为一个动作，建议顺序：

```text
处决交互候选
→ 空中/下落攻击
→ 冲刺攻击
→ 翻滚或后撤派生攻击
→ 蓄力释放
→ 当前姿态普通攻击
```

处决必须要求明确交互输入或“攻击键在处决候选内”的二次确认，避免玩家只想普通攻击却被吸附到错误目标。

### 连段链（L-07，当前原型）

轻/重攻击由 `AttackData` 的 chain 字段串成连段，无需全局连招表：

- `combat/data/attack_data.gd`：`next_light` / `next_heavy`（下一段 action_id，空 = 无链）、`chain_open_seconds` / `chain_close_seconds`（链窗开/关，0.0 表示按 windup+active+recovery 推导）、`chain_requires_hit`（链续需命中，挥空则不可续招）。
- `player/player.gd`：`_combo_chain_*` 状态缓存当前链（`_combo_chain_index` / `_combo_chain_length` / `_combo_chain_kind` / `_combo_chain_id` / `_combo_chain_attacks` / `_combo_chain_hit_landed`）。中立轻/重起手建档；链窗内再次输入由 `_try_chain_advance()` 缓冲推进，`_commit_chain_attack()` 落地下一段。
- 动作族推导兜底：无显式 `next_*` 时按 `semantic_id` + 武器类别推导链长（`_fallback_chain_length`）。
- 重置条件：冲刺、翻滚、跳跃、蓄力均清空连段缓存。

连段不是“无限复读”：`chain_requires_hit` 要求命中才能续招，链窗关闭后不可再补输入。

## 单持、双持与成对持握

| 维度 | 单持 | 双持 | 成对持握 |
|---|---|---|---|
| 定义 | 主武器单手控制，副手保留独立功能 | 双手共同控制同一主武器 | 两件配对武器分别占用左右手 |
| 姿态 | 侧身，副手侧受保护 | 胸口更正对目标，重心更低 | 正面或斜向，左右脚交替推进 |
| 防御 | 可使用盾、法器、偏转工具 | 通常失去盾牌格挡 | 依武器设定获得交叉防御或无防御 |
| 覆盖 | 精确、恢复快 | 更远、更宽、更高削韧 | 多段、追击、绕侧 |
| 精力 | 基准 | **×1.5** 精力消耗 | 由命中段数和位移共同决定 |
| 伤害 | 基准 | **×1.3** 伤害（削韧同倍率） | 成对略有节奏加成，非暴击翻倍 |
| 致命伤害 | 读取武器致命倍率 | 不因双持直接翻倍 | 只在配对处决动作中按专属倍率结算 |

双持不是简单的伤害开关。姿态改变后必须同时更换动作组、踏步、削韧、精力和兵器诀分支。当前兼容原型固定：**双持伤害 ×1.3、精力 ×1.5**；`critical_multiplier` 不随双持翻倍。

### 跳劈（Jump / Falling Attack）资格

跳劈按**左右手 `weapon_type`** 判定，不是按风格名猜测：

| 持握 | 条件 | 结果 |
|---|---|---|
| 双持 `two_handed` | 主手类型属于可跳劈近战族（sword/axe/curved/dagger/fist/hammer/spear） | 允许 |
| 成对 / 单持 | 左右手 `weapon_type` **相同**且属于可跳劈近战族 | 允许 |
| 其它（如剑+盾、弓+匕） | 类型不同或非近战 | **禁止**（攻击不生效） |

命中 payload 携带出招手的 `item_id`、`weapon_type`、`grip_mode`，左右手分算。

### 战斗提示模式（设置）

- 设置键：`combat_tip_mode` / bridge `combatTipMode`
- **默认关闭**；规则与数值始终生效，仅 HUD 教学文案受开关控制
- 暂停菜单 → **Combat Tip Mode** → `Show combat tips (charge / grip / context)`
- 持久化到 `user://ashen_hollow_settings_v1.json`

开启后显示的教学提示包括：

| 类别 | 示例文案 |
|---|---|
| 蓄力 | `CHARGING`、`CHARGE T1/T2/T3` |
| 语境攻 | `SPRINT / ROLL / BACKSTEP / JUMP / FALLING ATTACK` |
| 跳劈拒绝 | `JUMP SLASH NEEDS MATCHED WEAPONS` |
| 持握 | `GRIP LOCKED`、单持/双持/成对名称 |
| 兵器诀 | `SHIELD BASH`、`PIERCE THRUST`、`COLOSSAL / CRESCENT LEAP` |

**不**受提示模式关闭的文案：精力不足、弹反/破防/韧性反馈、关卡与余烬事件、Hitbox Debug 开关等。

## 武器类别姿态与动作定位

### 直剑

- 单持轻击采用短水平弧与快速回收，副手保持防御能力。
- 单持重击以踏步直刺为主，服务于盾缝、狭窄通道和精确惩罚。
- 双持轻击形成斜斩与回斩的稳定二连。
- 双持重击为过肩下劈，可在后半蓄势获得有限霸体。
- 定位：低门槛、稳定、处决倍率中等，适合学习完整战斗语法。

### 大剑

- 单持强调盾前横切后回正，不允许像直剑一样低风险连续挥砍。
- 双持轻击以髋部旋转和横向踏步扩大多目标覆盖。
- 重击使用拖地上挑、低位画弧或踏步重劈。
- 定位：范围、削韧和读招惩罚；空挥后必须暴露明显反击窗。

### 特大剑与巨锤

- 双持是主要姿态，膝部下沉、武器靠肩或垂地。
- “轻击”只是相对较短承诺的横扫或下砸，不代表快速。
- 重击限制末段转向，以最大覆盖、冲击阈值和霸体交换长后摇。
- 每次攻击必须包含踏地、转髋或推进，避免原地挥动与武器重量脱节。
- 定位：打盾、换血、区域压制；弱点是绕后和诱导空挥。

### 长枪与矛

- 单持与盾组合时沿中线推进，保留正面防护。
- 双持连续刺击强化距离控制，重击可转为冲锋终结刺或末端横扫。
- 近身最低有效距离内降低伤害与削韧，防止枪尖贴身仍全额命中。
- 定位：反翻滚、封通道、追击；弱点是侧面、绕背和贴身。

### 斧与战锤

- 轻击使用短弧斜砍或斜砸，维持近身压力。
- 重击由下沉、转髋和武器头落点构成，命中时强化停顿与冲击反馈。
- 战锤重击可携带小范围地面冲击，但实体命中与冲击波必须分别结算。
- 定位：打硬直、削韧、破盾；弱点是距离和恢复。

### 曲剑与双刀

- 单持由手腕和前臂主导，踏步轻快但单次削韧低。
- 成对动作使用交叉步、非对称双切和绕侧位移，避免镜像机械感。
- 重击可为十字前冲、旋身双切或短跃交叉下斩。
- 定位：多段、追击、侧绕；弱点是格挡、反击和重武器霸体。

### 拳套与爪

- 天然采用成对持握，肘部收紧、前脚探出、重心低。
- 轻击由刺拳、摆拳、肘击或爪击构成，位移是短滑步。
- 重击可为蓄力直拳、双拳锤击或短跳膝击。
- 可配置高风险偏转，但不能同时拥有长距离、强偏转和高削韧。
- 定位：短距离连段、打断和偏转；弱点是覆盖极短。

### 匕首

- 轻击为贴肋短刺切，重击通过低位假动作或绕侧切入。
- 常规伤害低，致命倍率和处决动画效率高。
- 定位：弹反处决、背刺和追击；不能靠高基础伤害替代定位。

## 兵器诀（Weapon Art）

《焰渊》将武器特殊动作统一称为 **兵器诀**，其中与烬直接共鸣的专属版本可称 **烬式**。兵器诀不是“普通攻击伤害乘二”，而是改变局面、姿态或资源交换方式。

| 武器类别 | 原创兵器诀 | 输入分支 | 战术意义 |
|---|---|---|---|
| 直剑 | 镇火架势 | 轻：破盾刺；重：迎击上挑 | 反格挡、反贪刀 |
| 大剑 | 裂岳步 | 轻：重踏横扫；重：追加下劈 | 多目标压制 |
| 特大剑 | 炉门镇压 | 释放：霸体下砸；蓄满：短震波 | 换血和区域封锁 |
| 长枪 | 破阵冲 | 轻：短冲；重：举盾冲锋终结刺 | 逼退、追击和队列突破 |
| 战锤 | 震脉击 | 地面冲击或弱点集中打击 | 快速积累处决槽 |
| 曲剑 | 流月回旋 | 侧步后双斩；命中可换侧 | 绕盾和惩罚慢武器 |
| 拳套 | 伏火偏转 | 成功偏转后肘击或抱摔终止 | 高风险反击替代 |
| 匕首 | 影步剔骨 | 短位移；背部命中强化致命槽 | 追背和处决构筑 |
| 盾牌 | 推盾反制 | 格挡后盾击；蓄力推盾打精力 | 破坏被动防守 |

### 兵器诀成本规则

每个兵器诀至少承担以下成本中的两项：

- Focus 消耗。
- 精力消耗。
- 明显前摇或后摇。
- 可被普通攻击打断。
- 冷却或每次休息次数。
- 位置、命中、格挡成功或姿态前置条件。

纯攻击型兵器诀通常同时消耗 Focus 与精力；架势和反制型可以低 Focus，但必须承担失败恢复。所有费用在动作启动、命中或分支确认的哪个时点扣除，必须写入招式数据，不允许各函数自行约定。

## 格挡、盾牌架势与破防

### 三种独立资源

| 数值 | 所有者 | 用途 | 归零结果 |
|---|---|---|---|
| Stamina | 角色 | 攻击、闪避、冲刺和格挡共享资源 | 无法继续行动；举盾再受有效冲击触发破防 |
| Guard Meter | 盾牌或防御工具 | 表示装备承受连续冲击的能力 | 立即 `GUARD_BROKEN`，不取决于剩余 Stamina |
| Poise | 角色 | 抵抗普通受击硬直 | 进入 `STAGGER`；不自动获得处决资格 |
| Execution Break | 指定大型敌人或弱点 | 表示可处决破绽积累 | 进入 `WEAK_POINT_EXPOSED` |

现有 `GuardResolver` 已实现朝向、吸收、稳定性和精力不足破防。目标版本在此基础上增加 Guard Meter 与单次冲击阈值。

### 推荐计算

```text
GuardStaminaCost = AttackGuardPower × (1 - ShieldStability) × GuardAngleFactor
GuardMeterDamage = AttackImpact × ToolGuardMultiplier
```

- `ShieldStability` 范围为 `0.0–0.95`，降低精力损失，不是直接破防阈值。
- `GuardAngleFactor` 在盾面中心最低，接近盾角边缘时升高。
- `direct_break_threshold` 表示单次冲击足以击穿该防具的门槛。
- `unblockable` 绕过格挡；`grab` 使用独立抓取解析；二者不能靠把伤害设得极高伪装。

### 破防结果

```text
正面格挡请求
├─ 不在盾角 / 不可格挡 → 常规受击
└─ 在盾角
   ├─ 单次冲击超过直接击穿阈值 → GUARD_BROKEN
   ├─ Guard Meter 归零 → GUARD_BROKEN
   ├─ Stamina 足够 → 吸收伤害并扣资源
   └─ Stamina 不足或为零后再次受击 → GUARD_BROKEN
```

- 人型角色破防后可产生正面处决候选。
- 非人型角色破防后只进入短硬直或弱点暴露。
- 玩家破防后的受控时间必须短于多数敌人的完整重击前摇，避免必死连锁。

## 韧性与霸体

韧性只决定是否发生普通硬直，不决定生命伤害，也不直接等同处决槽。

### 目标模型

```text
EffectivePoiseDamage = IncomingPoiseDamage × (1 - ArmorPoiseReduction)
ActionPoise = BasePoise × ActionArmorModifier
PoiseRemaining = ActionPoise - accumulated EffectivePoiseDamage
```

- `BasePoise` 来源于角色与装备。
- `ActionArmorModifier` 由招式阶段决定，只有指定 active 窗可大于零。
- 霸体不是无敌：生命伤害照常结算，Poise 仍会被消耗。
- Poise 归零触发短硬直；Boss 的 Execution Break 由独立弱点系统累计。
- 当前原型的 `hyper_armor: bool` 只是过渡实现，最终应由连续值替代。

## 弹反、背刺与处决

### 人型处决来源

| 来源 | 触发状态 | 空间要求 | 结果 |
|---|---|---|---|
| 弹反 | `PARRY_VULNERABLE` | 正面处决锚点内 | Riposte / 正面处决 |
| 盾破 | `GUARD_BROKEN` | 正面处决锚点内 | 踢开防具后致命攻击 |
| 背刺 | 目标允许背刺且玩家位于背部扇区 | 背部锚点、短距离、地面稳定 | 背刺配对动作 |
| 特殊兵器诀 | 数据明确授予处决候选 | 依兵器诀 | 拳套、匕首等专属致命动作 |

处决伤害建议：

```text
CriticalDamage = WeaponBaseCritical × ExecutionProfileMultiplier × VulnerabilityModifier
```

双持不直接让处决伤害翻倍；匕首等武器通过致命倍率体现定位。

### 处决启动约束

- 目标必须处于明确易处决状态，不能只检查剩余 HP。
- 攻击者与受害者各自进入独立受控状态。
- 启动前预留空间检测，避免穿墙、跌落或多目标重叠。
- 双方吸附到同一个 `ExecutionAnchor`，再锁定位置与朝向。
- 伤害只在动画事件点结算一次，不能在开始吸附时提前扣血。
- 同一目标同时只允许一个处决所有者。
- 目标死亡、地形失效或攻击者受强制中断时必须有安全取消路径。

## 非人型与 Boss 弱点处决

大型敌人不复用人类胸口刺击。每个主 Boss 使用独立 `Execution Break` 与弱点锚点。

| Boss | 弱点 | 主要积累方式 | 处决表现 | 叙事限制 |
|---|---|---|---|---|
| 巨阙 | 膝关节、炉心 | 蓄力重击膝部、震脉击、机制破坏 | 攀上构装体，将武器刺入炉心 | 最终 10% 转入职责选择，不直接杀死 |
| 刑天 | 锁链、胸口神目 | 斩链、弹开荣誉反击、胸眼精确命中 | 攀上躯干攻击胸眼 | 终礼后写入 `ch2_xingtian_fate` |
| 九尾 | 真身尾根、幻烬玉核 | 正确识别真身、真实之镜、连续精准攻击 | 切断主尾并击裂玉核 | 救赎路线在 30% 提前停止战斗 |
| 玄霄 | 光腐融合核心 | 三人格反制、完整书信清醒窗 | 以四烬压制核心并固定人格 | 10% 进入飞升/归忆选择 |
| 烛阴 | 星核、颈部裂隙 | 前四章机制援助、终烬阶段破绽 | 登上龙首刺入星核 | 10% 后只进入终结裁决，不播放死亡处决 |

Boss 处决应是阶段奖励和叙事节点，而不是重复的人型暴击动画。

## 闪避、跳跃与抓投时序

以下仅为《焰渊》的初始调试区间，不是对其他作品帧数的复制。所有参数以秒存储，并在目标 60 FPS、30 FPS 与波动帧率下验证。

| 动作 | 初始总时长 | 初始有效窗 | 失败风险 | 成功奖励 |
|---|---:|---:|---|---|
| 轻翻滚 | 0.55 s | 0.18–0.32 s 全身无敌 | 距离短、耗精 | 可接低伤翻滚攻 |
| 中翻滚 | 0.68 s | 0.18–0.30 s 全身无敌 | 恢复较慢 | 通用稳定回避 |
| 重翻滚 | 0.84 s | 0.16–0.26 s 全身无敌 | 明显后摇 | 重甲生存取舍 |
| 后撤步 | 0.35 s | 默认无全身无敌 | 易被追击 | 快速进入后撤攻 |
| 跳跃 | 0.62 s | 仅下半身 `low_sweep` 免疫 | 落点暴露 | 跨低扫和地面波 |
| 跳攻 | 0.88 s | 不额外授予全身无敌 | 空中受击与落地恢复 | 高削韧与弱点积累 |
| 普通抓投前摇 | 0.90–1.60 s | 不可格挡/弹反，可走位或闪避 | 命中后高伤或状态 | 空挥后 0.8–1.3 s 惩罚窗 |
| Boss 抓投前摇 | 1.20–2.20 s | 依体积走位、翻滚或特定低扫跳跃 | 高伤、位置重置 | 空挥后 1.0–1.8 s 惩罚窗 |

抓投使用独立 `Area3D` 或 `ShapeCast3D`。命中后进入 `GRAB_INITIATOR` / `GRABBED` 配对状态，临时关闭常规移动与普通碰撞推挤；不得把 `grab` 当作普通伤害标签后继续走通用 Hitbox。

### 玩家抓投（L-14，当前原型）

玩家在 `LOCOMOTION` 地面状态下按抓投输入，经 `try_player_grab` 就近选择横前 `PLAYER_GRAB_RANGE`（2.4u）内、`can_be_grabbed()` 为真且大致正面（前向点积 > -0.15，身后目标走背刺）的踉跄人型目标，复用 `ExecutionPairedDirector` 执行配对抓取（`_execution_kind = &"grab"`，`critical_multiplier` ×1.9，短前摇 0.22s）。玩家主动抓取走 ExecutionProfile 结算，不进入敌人抓投的 GrabProfile 路径。

### 人型敌人抓投（L-14，当前原型）

- `enemy.gd` 的 `can_grab` 取 content 键 `can_grab`（显式 bool）> 守护默认 true > `body_type` 体型启发式（`_body_type_can_grab`）。
- 非守护人型使用短前摇抓投：`_ensure_human_grab_profile()` 生成 `GrabProfile`，`telegraph_seconds = 1.05s`，随后进入 `GRAB_WINDUP`；命中概率 `HUMAN_GRAB_CHANCE = 0.10`。
- Boss（守护）仍保留原有 `GrabPairedDirector` 配对路径（`_setup_boss_break_profile` 依 `grab_enabled` 生成 Boss 默认抓投）。

## 目标状态模型

当前原型的状态枚举仍以攻击三阶段、闪避、弹反、战技和硬直为主；格挡是 locomotion overlay。目标模型应明确区分易处决和配对动作状态：

```text
LOCOMOTION
├── ATTACK_WINDUP → ATTACK_ACTIVE → ATTACK_RECOVERY
├── DODGE
├── JUMP / AIRBORNE / LANDING
├── PARRY
├── CAST
├── WEAPON_ART
├── STAGGER
├── GUARD_BROKEN
├── PARRY_VULNERABLE
├── WEAK_POINT_EXPOSED
├── EXECUTION_INITIATOR
├── EXECUTION_VICTIM
├── GRAB_INITIATOR
├── GRABBED
└── DEAD
```

格挡可以继续作为 locomotion overlay，但 `GUARD_BROKEN` 必须是独立受控状态。若后续支持移动举盾、盾戳和格挡转兵器诀，应升级为层级状态或并行状态层，而不是继续增加布尔组合。

### 状态效果（L-10，当前原型）

`combat/data/status_effect.gd` 以纯逻辑（`RefCounted`，无场景依赖）定义四种状态，玩家与敌人双端持 `status_bar`（`status_id → {"stacks", "elapsed", "tick_accum"}`），由调用方驱动 `apply()` / `tick()`：

| 状态 | 规则 |
|---|---|
| 出血 bleed | 叠层累积，达 `burst_threshold`（100）触发爆发伤害并清零（含剩余层加权） |
| 狐火 foxfire | 按 stack 秒伤 DoT（tick 间隔 1s，持续 3s） |
| 迷心 confusion | 短暂反转玩家水平移动输入（仅影响移动，不影响镜头/交互），持续 2s |
| 中毒 poison | 低秒伤 DoT（tick 间隔 1s，持续 10s） |

敌方可自带 `status_inflict`（content 显式 > body_type 推断），命中后按 `normalize_inflict_entry` 规范化应用（支持 `{id: 数值}` 与 `{id: {stacks, chance}}`）。

## 当前实现与目标差距

| 子系统 | 当前原型 | 目标 |
|---|---|---|
| 普通攻击 | 每风格一组 light/heavy 标量 | 武器类别 + 姿态 + 上下文的 Moveset |
| 特殊攻击 | 9 类 WeaponArtData 已落盘；`_execute_weapon_art` match 分发保留（A-06） | 数据驱动兵器诀与分支 |
| 格挡 | 朝向、吸收、稳定性、精力不足破防 | 增加 Guard Meter、直接冲击阈值和处决候选 |
| 弹反 | 装备化窗口；成功使敌人长硬直 | 独立 `PARRY_VULNERABLE` 与正面处决 |
| 韧性 | 敌人累计值；玩家二值霸体 | 玩家/敌人连续 Poise，Boss 独立 Execution Break |
| 持握 | 五套固定左右手组合 | 单持、双持、成对持握和通用切换 |
| 空中动作 | 两个风格专用 leap 战技 | 通用 jump、jump attack、falling attack |
| 处决 | 人型 riposte/backstab + Boss 弱点处决 | 事件点伤害与镜头已接；glb 动画可替换 |
| 抓投 | 程序化配对（GrabPairedDirector） | 独立抓取体积与配对状态；真实 glb 可替换事件名 |
| Boss 专属镜头 | CombatCameraDirector | 弱点暴露/处决/抓投/命运半身 |
| 命运选择 | FateChoiceOverlay | 字符串 `choice_flags`；对齐 chapter-bridge-map |
| 动画 | 程序化姿态和代码计时 | 数据契约驱动 AnimationTree / root motion |

## 实施顺序

1. 清理 `STYLE_TIMING`、`.tres` 与法术字典的多重数据所有权。
2. 建立 `AttackData`、`MovesetData`、`GuardProfile`、`ExecutionProfile` 和 `MovementActionProfile`。
3. 先把现有轻击、重击、leap、盾击和五种战技迁入新数据契约。
4. 扩展 Guard Meter 与 `GUARD_BROKEN`，保持现有格挡矩阵测试通过。
5. 实现连续 Poise，替换玩家二值霸体。
6. 实现人型正面处决与背刺，再接弹反处决。
7. 实现单持、双持、成对持握和上下文招式。
8. 实现蓄力、跑攻、翻滚攻、后撤攻、通用跳攻和下落攻。
9. 实现 Boss Execution Break 和专属弱点锚点。
10. 最后复用配对动作框架实现抓投，并接入 AnimationTree/root motion。

详细数据结构见 [attack-moveset-data-schema.md](attack-moveset-data-schema.md)，工程拆分见 [combat-expansion-roadmap.md](../tasks/combat-expansion-roadmap.md)。
